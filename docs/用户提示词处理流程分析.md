# 用户提示词处理流程分析

## 1. 主链路（普通 AI 对话）

### 1.1 前端输入与发送
- 用户在 AI 侧边栏输入后回车/点击发送，触发 `sendMessage(input.trim())`。
- 入口代码：
  - `frontend/src/components/AISidebar.tsx`
  - `handleSubmit` 调用 `sendMessage`。

### 1.2 前端组装上下文并请求后端
- `AIContext.sendMessage` 执行以下动作：
  - 先把用户消息写入前端消息列表；
  - 从终端上下文读取最近输出 `getRecentOutput(activeSessionId, 20)`；
  - 截取最近 6 条对话历史；
  - 请求后端 `POST /api/ai/chat`。
- 关键代码：
  - `frontend/src/contexts/AIContext.tsx`
  - `sendMessage` 方法内的 `fetch(${backendUrl}/api/ai/chat, ...)`。

### 1.3 后端控制器接入
- `AIController.chat` 接收 `ChatRequest` 并转发给 `AIService.chat`。
- 关键代码：
  - `backend/src/main/java/com/aiterminal/controller/AIController.java`
  - `backend/src/main/java/com/aiterminal/ai/dto/ChatRequest.java`

### 1.4 后端 AIService 处理
- `AIService.chat` 核心步骤：
  1. 决定 provider（请求参数优先，否则读取当前激活配置）；
  2. 使用 `ContextBuilder` 生成系统提示词和用户消息（含终端输出）；
  3. 分别调用 `callOllama` / `callOpenAI` / `callCustomAPI`；
  4. 从模型响应中解析命令卡片（command block / inline / code block）；
  5. 返回 `ChatResponse`。
- 关键代码：
  - `backend/src/main/java/com/aiterminal/ai/AIService.java`
  - `backend/src/main/java/com/aiterminal/ai/ContextBuilder.java`

### 1.5 前端渲染响应
- 前端收到 `ChatResponse` 后将 assistant 消息和 `commands` 渲染在 AI 面板。
- 关键代码：
  - `frontend/src/contexts/AIContext.tsx`
  - `frontend/src/components/AISidebar.tsx`

## 2. 终端上下文注入链路

### 2.1 终端输出采集
- 终端输出通过 WebSocket 二进制消息进入前端 `TerminalContext`。
- 前端会进行流式解码、行缓冲、噪音清理后写入 `outputBuffersRef`。
- 关键代码：
  - `frontend/src/contexts/TerminalContext.tsx`
  - `frontend/src/utils/terminalOutput.ts`

### 2.2 供 AI 使用
- `AIContext.sendMessage` 从 `getRecentOutput` 读取整理后的终端输出。
- 后端 `ContextBuilder` 再次做 ANSI 清理和长度截断，控制上下文体积。

## 3. 命令建议与执行分支

### 3.1 命令提取
- `AIService.parseCommands` 会识别以下格式：
  - ```command JSON 块
  - 行内 `command:{...}`
  - 普通代码块中疑似命令行
- 同时调用 `CommandGuard` 打风险等级。

### 3.2 前端执行
- 用户在命令卡片点击执行后，前端调用 `executeCommand`：
  - 记录执行前输出；
  - 向当前终端会话发送命令；
  - 等待短暂时间后取执行后输出；
  - 用前后差分提取新增输出并展示。
- 关键代码：
  - `frontend/src/components/CommandCard.tsx`
  - `frontend/src/contexts/AIContext.tsx`

## 4. ReAct 自动模式分支

### 4.1 前端启动任务
- 在 ReAct 面板输入任务后，前端 `POST /api/react/execute`，并通过 SSE 流接收步骤更新。
- 关键代码：
  - `frontend/src/components/ReActPanel.tsx`

### 4.2 后端执行循环
- `ReActController` 建立 `SseEmitter`，将步骤流式返回前端。
- `ReActAgent` 循环执行：
  1. 调用 LLM 生成 `THOUGHT/ACTION/ACTION_INPUT`；
  2. 若 `ACTION=EXECUTE`，先过 `CommandGuard`；
  3. 通过 `TerminalSyncExecutor` 在真实终端执行命令；
  4. 将执行输出反馈给下一轮推理；
  5. 到 `COMPLETE/ERROR/CANCELLED` 终止。
- 关键代码：
  - `backend/src/main/java/com/aiterminal/controller/ReActController.java`
  - `backend/src/main/java/com/aiterminal/ai/react/ReActAgent.java`

## 5. 总结

- 当前系统是“双通道提示词处理”：
  - 普通对话：`/api/ai/chat`
  - 自动执行：`/api/react/execute`（SSE）
- 两条链路共享终端上下文，核心目标是让“用户看到的终端状态”与“LLM感知的上下文”尽可能一致。
