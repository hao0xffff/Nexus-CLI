# 项目模块架构详细分析

## 1. 架构总览

该项目是一个典型的「桌面壳 + 前端渲染层 + 后端服务层 + 外部模型服务」四层结构：

- 桌面壳：Electron 主进程，负责窗口生命周期和后端进程管理。
- 前端层：React + xterm.js，负责 UI、终端展示、AI 面板与交互。
- 后端层：Spring Boot，负责 WebSocket 终端桥接、AI 编排、ReAct 执行、配置与安全策略。
- 外部服务层：Ollama / OpenAI / Custom API，提供模型推理能力。

## 2. 前端模块架构

### 2.1 核心模块职责

- `frontend/electron/main.ts`
  - 桌面入口，创建窗口并拉起后端进程。
- `frontend/electron/preload.ts`
  - 通过 `contextBridge` 暴露安全 API 给渲染进程。
- `frontend/src/contexts/TerminalContext.tsx`
  - 维护终端会话状态、WebSocket 连接、输出缓冲与清洗后的上下文。
- `frontend/src/contexts/AIContext.tsx`
  - 管理聊天状态、调用 `/api/ai/chat`、执行命令与差分输出。
- `frontend/src/components/AISidebar.tsx`
  - 聊天 UI、输入提交、消息渲染、命令卡片承载。
- `frontend/src/components/ReActPanel.tsx`
  - 自动任务执行入口，使用 SSE 消费步骤流。
- `frontend/src/components/Terminal.tsx`
  - xterm.js 实际渲染层，负责终端输入输出交互。

## 3. 后端模块架构

### 3.1 包级结构与职责

- `com.aiterminal.controller`
  - REST 接口层：AI 对话、ReAct 控制、配置与健康检查等。
- `com.aiterminal.websocket`
  - WebSocket 终端通信层：文本控制消息 + 二进制终端流转发。
- `com.aiterminal.terminal`
  - 终端会话域：
    - `ITerminalSession` 抽象接口
    - `PtySession / LocalSession / SSHSession` 实现
    - `TerminalSessionManager` 生命周期管理
    - `sync/TerminalSyncExecutor` 同步执行与输出采集
    - `profile/*` 平台与 shell 特征识别
- `com.aiterminal.ai`
  - AI 业务域：
    - `AIService` 多 provider 调用与命令提取
    - `ContextBuilder` 系统/终端上下文拼装
    - `CommandGuard` 风险控制
    - `react/*` ReAct 自动执行闭环
    - `config/*` 模型配置管理
- `com.aiterminal.config`
  - 应用配置、线程池与 WebSocket 注册。
- `com.aiterminal.util`
  - 系统检查、安全存储、输出工具。

## 4. 关键业务流拆解

### 4.1 用户问答流（Chat）

```text
用户输入
  -> AISidebar.submit
  -> AIContext.sendMessage
  -> 附带终端最近输出 + 历史消息
  -> POST /api/ai/chat
  -> AIController -> AIService
  -> 外部LLM推理
  -> 命令提取/风控标注
  -> 返回消息+命令卡片
  -> 前端渲染
```

### 4.2 自动执行流（ReAct）

```text
用户任务描述
  -> ReActPanel.startTask
  -> POST /api/react/execute (SSE)
  -> ReActAgent循环:
       思考(THOUGHT)
       行动(ACTION=EXECUTE/OBSERVE/COMPLETE)
       执行(TerminalSyncExecutor)
       观察(OUTPUT反馈下一轮)
  -> SSE逐步回传
  -> 前端展示步骤状态与输出
```

## 5. 架构优势与潜在改进点

### 5.1 当前优势

- 职责分层清晰：UI/会话/AI/执行器边界明确。
- 终端与 AI 上下文联动：具备“基于现场状态回答”的能力。
- 多 provider 可切换：配置化较完整。
- ReAct 采用 SSE：适合长任务与可视化步骤反馈。

### 5.2 可继续增强

- 文档层面统一 `doc` 与 `docs` 目录策略，避免知识分散。
- 为关键流程补充时序图（可配合 Mermaid）。
- 增加端到端回归测试：
  - chat 请求/响应契约
  - command card 执行回显
  - ReAct 取消与超时分支
- 进一步抽象前端输出清洗策略为可配置管线，便于跨平台差异适配。

## 6. 模块边界结论

项目整体是“终端驱动的 AI 助手系统”：

- 前端承担交互、会话态和实时展示；
- 后端承担编排、执行、风控和模型适配；
- 终端会话域是系统核心状态源；
- ReAct 在此基础上扩展为闭环自动执行能力。

该架构具备良好的扩展性，适合继续向“可观测自动化助手”演进。
